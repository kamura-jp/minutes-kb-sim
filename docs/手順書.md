# 手順書：議事録をナレッジに登録する

## 定常作業の流れ
1. `git switch main` → `git pull` → `git switch -c add/<日付>-<内容>` でブランチを作る。
2. 原資料を `data/raw/` に置く（ファイル名: `minutes_YYYY-MM-DD_<名前>.txt`）。
3. 原資料を読み、発言者・日付・出典を確認する。曖昧な内容は登録せず「確認事項」に書く。
4. `data/kb/` のYAMLにエントリを追加する（IDは続き番号、日付は YYYY-MM-DD）。
5. `python tools/validate.py` を実行し、エラー0件にする。
6. `git diff` で差分を確認する。意図しない変更がないか見る。
7. コミットして push し、Pull Request を作る（「変更内容」「確認方法」を書く）。
8. GitHub Actions が緑になったことを確認する。赤なら原因を調べる。
9. レビュー後にマージする。

## YAMLの書き方
```yaml
entries:
  - id: KB-0007
    title: 短い見出し
    body: 原資料の趣旨を変えずに1〜2文で書く。
    date: 2026-10-19
    source: minutes_2026-10-19_legal.txt
    speaker: 山本
    confidentiality: internal
```
- インデントは半角スペース2つ（タブは使わない）。
- `confidentiality` は `public` / `internal` / `confidential`。

## よくあるエラーと対処
| メッセージ | 原因 | 対処 |
|---|---|---|
| id が重複しています | 同じIDを2回使った | 続き番号に振り直す |
| date の形式が不正です | `2026/10/12` など | `2026-10-12` にそろえる |
| source が未入力です | 出典が空 | 原資料のファイル名を書く |
| confidentiality が不正です | 日本語など許可外の値 | 3つの値のどれかにする |
| source のファイルが見つかりません | ファイル名の打ち間違い | `data/raw/` のファイル名と照合 |

## エスカレーション（エンジニアに連携する条件）
- ツールの動作が手順書と違う、または原因が分からないとき。
- 自分で直せない検証エラーが出たとき。
- そのときは `docs/エラー報告テンプレ.md` の形で報告する。
